# Собственная локальная сборка FFmpeg — этап202

Исходная база — commit290a2c2d63b751fed15df187b5ec249db5d2c19f,
ArtLapse201. Цель: отдельный локальный кандидат с собственными CLI FFmpeg,
без изменения анализа, монтажа, UI, проектов и настроек. ZIP приложения не
создаётся; резервная папка/tag, исходная201 и ZIP199 сохраняются.

## Состав

- FFmpeg8.1.2, официальный подписанный release; tag commit
  `38b88335f99e76ed89ff3c93f877fdefce736c13`.
- x264 commit `0480cb05fa188d37ae87e8f4fd8f1aea3711f7ee`, все bit depth/chroma,
  CPU SIMD и Win32 threads; обязательный CPU-путь приложения.
- libvpx1.15.2: VP8/VP9, включая high bit depth; давние штатные native
  декодеры FFmpeg также сохраняются.
- dav1d1.5.3: программное декодирование AV1.
- Opus1.6.1 и zlib1.3.2: стабильные версии, SHA256 сверены с официальными сайтами.
- nv-codec-headers13.0.19.0: NVENC/NVDEC/CUVID; драйвер и GPU проверяются отдельно.
- Все штатные доступные декодеры/демультиплексоры/фильтры FFmpeg, без
  `--disable-everything` и списков урезанных форматов.

Не воспроизводится весь набор сторонних расширений Gyan full. Для приложения
проверяются MP4/MKV/MOV/WebM, H.264/HEVC/VP8/VP9/AV1, изображения,
MP3/WAV/FLAC/M4A/OGG/AAC/Opus/WMA, CPU/NVIDIA, proxy, preview, музыка,
заставки, презентация, компоновки, таймлапсы/Shorts и подрезка. Наличие
декодера само по себе не считается проверкой конкретного файла.

## Повторение сборки

Все команды выполняются локально, без изменения глобального PATH. Требуются
Windows x64, Python3.10+, установленный Git Bash, свободный временный диск W:.
На этой машине Visual Studio не содержит C/C++ toolchain; она не используется.
Исходный комплект содержит архивы библиотек, полный LLVM23.1.4 (включая
runtime) и MinGW-w64 соответствующей ревизии. Готовый универсальный
компилятор не включён внутрь source.tar: его исходный официальный ZIP
сохранён отдельно в downloads/llvm-verified.zip; URL/проверенный digest
зафиксированы в lock, загрузка — download_toolchain.py. Git Bash и Python
являются внешними общедоступными сборочными инструментами.

1. В новой папке скопировать packaging/ffmpeg и архивы из source-kit/archives
   в artifacts/ffmpeg-own-202/downloads. Получить официальный компилятор
   через `python packaging/ffmpeg/download_toolchain.py` или скопировать
   проверенный llvm-verified.zip из сохранённых downloads; не использовать partial-файлы.
2. Выполнить `python packaging/ffmpeg/prepare_inputs.py`. Команда сверяет
   размеры/хеши и распаковывает новые каталоги. Существующие деревья не
   перезаписывает; для чистого повторения нужна отдельная новая рабочая папка.
3. Установить сохранённые Meson1.9.1/Ninja1.13.0 wheel через
   `python -m pip install --no-index --no-deps --target
   artifacts/ffmpeg-own-202/tools/python <оба wheel>`.
4. Создать `subst W: <полный путь к artifacts/ffmpeg-own-202>`.
   Это короткое имя существующей разрешённой папки, а не перенос файлов:
   FFmpeg запрещает пробелы в source path. Сначала проверить, что W: свободен.
5. `python packaging/ffmpeg/build.py deps` — зависимости;
   `python packaging/ffmpeg/build.py ffmpeg` — оба CLI и install.
   `refresh`, `deps-tail`, `ffmpeg-resume` служат для продолжения локальных
   попыток; чистая сборка использует первые две команды.
6. После окончания снять только собственное сопоставление: `subst W: /D`.

Результаты: `installed/bin/ffmpeg.exe`, `installed/bin/ffprobe.exe`.
Конфигурация/команды/диагностика — logs и `sources/ffmpeg-8.1.2/ffbuild`.
Сборка ограничена4 заданиями; CLI — статическая компоновка зависимостей,
системные Windows DLL остаются динамическими. Скрытые дополнительные
runtime DLL проверяются отдельно по PE imports и запуском с очищенным PATH.

## Особенности Windows и патчи

Патчи хранятся в `packaging/ffmpeg/patches` и исходном комплекте.
Они записаны без контекстных строк, чтобы вложенный diff не создавал
ложные ошибки whitespace при проверке Git. Для ручного применения:
`git apply --unidiff-zero <patch>`. Все4патча отдельно применены к чистым
файлам из архивов; результат совпал с реально скомпилированными исходниками
(`patch-smoke.json`). Обязательная проверка Git whitespace не отключалась.

- dav1d: относительные NASM include вместо физического пути с кириллицей.
- FFmpeg: release-файл VERSION переименован в FFMPEG_RELEASE_VERSION,
  `ffbuild/version.sh` читает новое имя. На регистронезависимой Windows
  прежний VERSION перекрывал стандартный C++ заголовок `<version>`.
- FFmpeg gfxcapture: явный `<system_error>` для современного libc++;
  сохранён сам фильтр и прочие возможности.
- FFmpeg: response-файлы для архиватора пишет встроенная `$(file ...)`
  GNU Make вместо длинного shell echo; полный набор object-файлов сохранён.
- libvpx: сгенерированные `.mk` используют `W:/` вместо `/w/`, обязательно
  LF (CRLF нарушал сравнения `yes` в штатном Perl-генераторе RTCD).
  Отключено только отслеживание инкрементальных header-зависимостей,
  несовместимое с физическим Unicode-путём в Windows Make.
  Компиляционные оптимизации и runtime CPU dispatch сохраняются.
  Очистка ограничена генерируемыми object/dependency/RTCD-файлами внутри
  распакованного libvpx; исходные файлы и другие каталоги не удаляются.

Сверка всех исходных файлов реально скомпонованных библиотек:12721 файл
побайтно совпал с архивами;4изменённых файла и переименование VERSION
полностью объясняются сохранёнными патчами. Результат:
`source-correspondence.json`. Хеши19статических входных архивов —
`link-inputs.json`. Равенство бинарников при повторной сборке на другой
машине не проверялось и не обещается.

## Лицензии и предел результата

CLI конфигурируется GPLv3+ (`--enable-gpl --enable-version3`), без nonfree.
Новые сборочные/проверяющие Python-скрипты в packaging/ffmpeg предоставляются
по GPL-3.0-or-later (SPDX в каждом файле, полный текст в packaging/ffmpeg/COPYING).
Это отдельная область лицензирования; лицензия собственного кода ArtLapse
не изменяется. Патчи сохраняют применимые лицензии соответствующих upstream.
Комплект должен включать точные исходные архивы, изменения, сборочные
скрипты, конфигурацию и copyright/лицензии всех скомпонованных компонентов.
Код ArtLapse и старые проекты в этот исходный архив не подмешиваются.
Qt/PySide, FFmpeg DLL Qt Multimedia и прочие DLL базы201 не пересобираются:
их незавершённый аудит194 остаётся отдельным. Публичная готовность всего
приложения не утверждается, push/публикация/сообщения не выполняются.

Фактические результаты проверок и итоговые пути записываются в PROGRESS.md
и отчётах `artifacts/ffmpeg-own-202`; этот документ не заменяет запуск тестов.
